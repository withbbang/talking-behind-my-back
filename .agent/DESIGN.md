## 원칙
- 모바일 우선. 기준 뷰포트 390×844(iPhone), 데스크톱 ≥1024에서 사이드바 고정.
- 입력창은 항상 하단 고정(키보드 올라와도 가려지지 않게 `100dvh` + safe-area).
- 스트리밍 중에도 레이아웃이 튀지 않도록 말풍선은 아래로만 자란다.
- 접근성: 모든 버튼 `aria-label`, 스트리밍 말풍선 `aria-live="polite"`, 포커스 링(`--accent` 2px) 유지. 색만으로 상태 구분 금지.
- 다크/라이트: 기본은 시스템 설정. 사이드바 하단 테마 선택(`시스템 | 라이트 | 다크`, T-020/D-024)으로 수동 고정 가능 — 선택은 기기별(`localStorage`), 첫 페인트 전 적용. `surface`/`on-surface` 는 모드에서 반전(BRAND.md#2).
- **심플**: 화면당 주 액션 1개. 아이콘 버튼은 라벨 없이 쓰되 44×44 터치 영역. 구분선 대신 여백(16/24px). 그림자 없음.
- **귀여움**: 모서리 ≥16px(말풍선 22px, 시트 28px, 필 9999px). 등장 모션은 `bubble-in` 1회(scale .96→1, 180ms), `prefers-reduced-motion` 시 즉시. 아바타는 `icon.svg` 하트만.

## 화면

### 1. 로그인 `/login` (구현됨, T-005)
- 상단: 제목 "뒷담 친구"(중앙, 800, `clamp(3rem,15vw,4.5rem)`), 소개문 2줄 우측 정렬 `muted`.
- 하단: 말풍선 시트(`surface`, 라운드 28, 왼쪽 아래 꼬리)에 소셜 버튼 3개(세로, 각사 브랜드색). 세션 확인 중엔 스켈레톤 3줄.
- 오류(`?error=`): 상단 토스트 — `access_denied` "로그인 취소했네? 다시 시도해봐!", `authorization_request_not_found` "로그인 시간이 지났네? 처음부터 다시 해봐!", 그 외 "로그인에 실패했네? 잠시 후 다시 시도해봐!". 약관/개인정보 링크 없음(v1).
- `?next=` 있으면 로그인 후 그 경로로(T-018 `/join/{code}` 왕복).

### 2. 채팅 셸 (`(chat)/layout.tsx`)
- 모바일: 상단 바 56px — 좌 햄버거 · 중앙 방 제목(1줄 말줄임, 탭하면 방 헤더 시트) · 우 보이스 모드 토글(M3, 그 전엔 숨김). 햄버거 → 사이드바 드로어(폭 300, 뒤 `ink` 40% 딤).
- 데스크톱: 좌측 사이드바 280px 고정 + 메인. 상단 바는 메인 안에.
- 사이드바
  - 상단 "+ 새 방" 주 버튼 → `POST /rooms` 즉시 생성 → `/rooms/{id}` 이동. (draft `/` 폐기, D-010 대체.)
  - 방 목록 항목 높이 64: 좌 아바타(방에 사람이 2명이면 사람 아바타, 혼자면 AI 하트) · 제목 1줄 말줄임 · 우측 상대 시간 `muted` 12px.
    제목 아래 보조 줄 13px `muted`: `방장` 배지(내가 OWNER) 또는 상대 닉네임(PARTICIPANT). ORPHANED 방은 `닫힘` 배지 + 제목 `muted`.
  - 항목 … 메뉴(길게 누르기/호버 아이콘): 제목 수정(개설자만, 인라인 Input) · 나가기(ConfirmDialog "나가면 이 방은 끝이야.\n진짜 나갈거야?" / 참여자는 "나가면 이 방 대화는 앞으로 볼 수 없어.\n진짜 나갈거야?").
  - 상단 도달 시 이전 페이지 로드(키셋 커서). 빈 목록: 하트 아바타 + "아직 방이 없네? 하나 만들자!" 한 줄.
  - 하단: 프로필(아바타 + 닉네임) · 로그아웃 텍스트 버튼. 그 아래 한 줄에 테마 선택 필 토글 `시스템 | 라이트 | 다크`(PillToggle, `aria-label` "테마 선택", 좌측 보조 라벨 없음, 우측 정렬). 드로어에서도 같은 위치(T-020, D-024).

### 3. 채팅방 `/rooms/[id]`
- **방 헤더 시트** (상단 바 제목 탭 → 바텀 시트)
  - 멤버 줄: 아바타 2칸(빈 자리는 점선 원 + "초대" — 개설자만 탭 가능 → 초대 공유 시트 §4).
  - 모드 필 토글 `AI` | `유저끼리`. 혼자면 비활성 + 밑에 13px `muted` "친구 초대해봐!". 변경 즉시 `PATCH mode`, 실패 시 토스트 + 되돌림. 실패 토스트는 `MODE_NOT_ALLOWED` 만 "혼자서는 유저끼리 대화할 수 없어!", 그 외 공용 오류 문구(서버 메시지 노출 없음, D-025).
  - AI 성격(개설자만 편집, 참여자는 읽기 전용 표시): 프리셋 필 토글 `차분한 편` | `공감형` (RATIONAL/EMOTIONAL) + 아래 "직접 쓰기" 접이식 textarea(라운드 16, 최대 2,000자, 우하단 `n/2000`, "되돌리기" 텍스트 버튼). 저장은 blur/버튼 → `PATCH aiPrompt`. 현재 적용 문구(`effectiveAiPrompt`)는 textarea 위 13px `muted` 2줄 말줄임으로 항상 표시.
  - 제목 수정(개설자만): 상단 제목 자체를 탭 → Input.
- **메시지 목록** (말풍선 3종, 최대 폭 78%)
  | 종류 | 정렬 | 면 | 꼬리 | 부가 |
  |---|---|---|---|---|
  | 나(USER, 본인) | 우 | `surface`/`on-surface`, 라운드 22, 우하단 6 | 없음 | 시간 12px `muted` 아래 우측 |
  | 상대(USER, 상대 멤버) | 좌 | `bg` + `ink` 12% 테두리, 라운드 22, 좌하단 6 | 없음 | 위에 닉네임 12px `muted`, 사람 아바타 |
  | AI(ASSISTANT) | 좌 | `bg` + `ink` 12% 테두리, 라운드 22, 좌하단 6 | 없음 | AI 하트 아바타, 시간 줄 앞 듣기 버튼(T-010). **상대(USER) 말풍선과 완전히 같은 모양** — 아바타·듣기 버튼으로만 구분(2026-09-18 D-030) |
  - 같은 발신자 연속 메시지는 아바타·닉네임 생략, 간격 4px(다른 발신자 12px). 날짜 바뀌면 중앙 12px `muted` 날짜 칩.
  - VOICE 입력 메시지: 시간 옆 작은 마이크 아이콘 14px.
  - `mode`/`member` 이벤트: 중앙 시스템 라인 13px `muted` — "유저끼리 대화 가능!" / "AI랑 대화 가능!", "영희 등장!", "영희 퇴장!".
  - 스트리밍: 첫 delta 전 AI 말풍선 자리에 점 3개 튀는 애니메이션(귀여움 포인트, 700ms 루프, reduced-motion 시 정적 "…"). delta 오면 텍스트 + 끝 커서 `▍`. `error` 이벤트 → 그 말풍선에 "시스템 오류. 다시 시도해줄래?" + "다시" 텍스트 버튼(같은 content 재전송).
  - 상단 도달 시 이전 페이지. 재연결 시 놓친 메시지 보충 후 목록 뒤에 붙임(스크롤 위치 유지).
- **입력창** (하단 고정, 패딩 12, `bg`)
  - 라운드 24 캡슐: textarea(자동 높이, 최대 5줄) · 마이크 버튼(M3, 그 전엔 숨김) · 전송 버튼(원 40, `surface`, 화살표 아이콘).
  - 본인 잡 진행·대기 중엔 textarea·전송 비활성(플레이스홀더 "뒷담 친구 기다리는 중...") — 상대는 입력 가능.
  - HUMAN 모드 플레이스홀더 "AI 몰래 얘기하기". AI 모드 "무슨 얘기 하고싶어?".
  - 오류: 409 `ROOM_BUSY` → 토스트 "아직 답 쓰는 중. 좀만 기다려줘!". 503 → "지금 바쁘니깐 잠깐 뒤에 다시 해봐!". 400(길이 초과 등) → "불가능한 요청이야!". 410 → ORPHANED 모달(§6). 그 외 → 공용 오류 "시스템 오류. 다시 시도해줄래?".
- **빈 방**(메시지 0 **이고 시스템 라인도 0**): 중앙 AI 하트 아바타 64px + "오늘은 누가 짜증나게 했어?" 한 줄. 예시 칩 없음(심플). 친구가 들어와 "영희 등장!" 라인이 생기면 빈 상태 대신 목록(라인만)을 보인다(T-024, 2026-09-16 사용자 결정).

### 4. 초대 공유 시트 (개설자 전용, 바텀 시트)
- 제목 "친구 데려오기". 중앙 QR(200px, 클라이언트 생성 `uqr` 행렬 → SVG 직접 렌더, 모듈은 둥근 사각형 `rx` ≈ 모듈의 35%, 오류정정 M, 로고 없음).
  QR 카드는 라운드 16, 패딩 16, **모드 무관 라이트 토큰 고정**(`--qr-bg`=`#fff4f8`, `--qr-ink`=`#2b0a1a`, globals.css 상수) — 다크에서도 어두운 모듈/밝은 바탕이라 스캐너 호환.
- 코드 8자를 4+4 로 띄워 표시 "K7Q2 M9XW"(24/700, 자간 0.12em, `tabular-nums`) + 우측 복사 아이콘 버튼. 복사되는 값은 8자 연속. 탭 시 토스트 "복사 완료".
- 주 버튼 "링크 복사"(`inviteUrl`). `navigator.share` 가 있을 때만 보조 버튼 "공유하기"(제목 = 방 제목, url = `inviteUrl`). 없으면 버튼 자체를 렌더하지 않는다.
- 하단 텍스트 버튼 "코드 다시 만들기" → ConfirmDialog "이전 코드는 사용할 수 없어.\n새로 만들까?" → `POST invite/regenerate` → 시트 내용 갱신.
- 참여자에겐 이 시트 진입점 없음(빈 자리 원도 탭 불가).

### 5. 입장 `/join/{code}`
- 미로그인: `/login?next=/join/{code}` → 소셜 버튼이 `?next=` 를 api 로 전달 → 콜백이 `next` 로 302(D-021, T-022).
- 레이아웃: 로그인과 같은 골격 — 상단 제목 "초대장 도착"(중앙), 소개문 자리(우측 2줄 `muted`) "{ownerNickname}의 방 / 같이 뒷담화하자!".
  하단 말풍선 시트(`surface`, 라운드 28, 왼쪽 아래 꼬리)에 방 제목(17/600) · 멤버 `n/2` · 주 버튼 "들어가기"(`bg`/`ink`, 시트 안 반전). **꼬리 발치에 개설자 이니셜 아바타 28px** — 개설자가 말 거는 장면. 이 화면의 유일한 장식.
  성공 → `router.replace('/rooms/{id}')`. 미리보기 로딩 중엔 시트 안 스켈레톤 2줄(로그인과 동일).
- 실패(미리보기 단계에서 판정, 시트 안 문구 + 보조 버튼 "내 방 가기"):
  | 코드 | 문구 |
  |---|---|
  | 404 `INVITE_NOT_FOUND` | 그런 방 없는데? |
  | 409 `ROOM_FULL` | 여긴 벌써 꽉 찼어 |
  | 410 `ROOM_ORPHANED` | 방장이 도망간 방이야! |
  | 400 `SELF_INVITE` | 네 방 아니야? |
  | 409 `ROOM_LIMIT_EXCEEDED` | 방이 50개 넘었어. 정리하고 와! |
  | 409 `PAIR_ROOM_EXISTS` | 걔랑은 이미 대화하고 있어! |
- 이미 멤버(`alreadyMember: true`)도 버튼 문구는 같은 "들어가기"(D-025, 재입장 구분 없음). 실패·기타 오류(네트워크 등): 시트 안 "시스템 오류. 다시 시도해줄래?" + 주 버튼 "다시".

### 6. 주인 없는 방 모달 (참여자, ORPHANED)
- 트리거: 목록에서 ORPHANED 방 탭 / 방 안에서 `member` 이벤트 `roomStatus: ORPHANED` / 요청 410.
- ConfirmDialog: 제목 "이용할 수 없는 채팅방이야." 본문 "방장이 도망간 방이야!" 버튼 1개 "나가기" → `DELETE /rooms/{id}` → 목록에서 제거 → 남은 방 첫 항목 또는 빈 상태로.
- 뒤 채팅 내용은 딤 처리(`ink` 40%), 모달 닫기 없음(확인만).

### 7. 보이스 모드 (오버레이, M3 — 2026-09-18 D-029 개정)
- 진입: 상단 바 우측 토글(`Waveform` 아이콘, `aria-label` "음성", `aria-pressed`). **AI 모드이고 ORPHANED 아닐 때만** 보인다. 오버레이 중 HUMAN 으로 바뀌면 종료 + 공용 오류 토스트 대신 "AI 모드에서만 돼!"(초안).
- 전체 화면 오버레이 `bg` 96% + 뒤 목록 흐림, `role="dialog"` `aria-label` "보이스 모드".
- 중앙: **말하는 쪽으로 뒤집히는 말풍선 2개**(원 대신, D-029). 활성 말풍선만 100%, 반대쪽은 45%.
  | 상태 | 활성 말풍선 | 안 | 라벨 |
  |---|---|---|---|
  | `recording` | 우측 `surface`/`on-surface`, 라운드 26, 우하단 꼬리 6 | 세로 바 5개 등락(CSS, 700ms 루프) + `m:ss` `tabular-nums` | 듣는 중 |
  | `transcribing` | 우측 동일 | 점 3개(`typing-dots`) | 받아적는 중 |
  | `streaming` | 좌측 `bg` + `ink` 12% 테두리, 좌하단 꼬리, 하트 아바타 | 응답 델타 미리보기 15px 4줄 말줄임 | 답하는 중 |
  | `speaking` | 좌측 동일 | 펄스(scale 1↔1.04) | 말하는 중 |
  라벨은 말풍선 아래 13px, `aria-live="polite"`. `prefers-reduced-motion` 이면 모든 모션 정지(정적 표시).
- 하단: 보조 버튼 "다시"(현재 단계 취소 → recording) · 텍스트 버튼 "끄기".
- 60초 상한: 녹음이 60초에 닿으면 자동 종료 → transcribing, 토스트 "60초까지만 들을 수 있어!"(초안). STT 결과가 비면 토스트 "아무 말도 안 들렸는데?"(초안) 후 recording.
- 권한 거부: 말풍선 대신 카드 + "마이크 좀 열어줘. 브라우저 설정에서." + "다시"(권한 재요청) / "끄기". 네트워크·전송 오류: 좌측 말풍선에 문구("시스템 오류. 다시 시도해줄래?", 409 는 "아직 답 쓰는 중. 좀만 기다려줘!") + "다시".
- 루프: recording → STT → `POST messages`(`inputType: VOICE`) → `replyTo` 가 내 messageId 인 스트림만 추적 → `done` 뒤 assistant content 를 `/speech/tts`(1,000자 초과는 문장 경계 분할 순차) → 재생 끝 → recording. 2인 방에서 상대 메시지의 응답은 목록에만 남고 읽지 않는다(D-029).
- 컴포저 마이크(오버레이 밖): 캡슐 안 전송 버튼 왼쪽 40px 원(`ink` 12% 테두리, `aria-label` "마이크"). 탭 → 캡슐이 녹음 줄로 바뀜: `accent` 점 펄스 + "듣는 중" + `m:ss` + X(`aria-label` "녹음 취소") + ✓(`aria-label` "녹음 완료"). 완료 → "받아적는 중" 점 3개(비활성) → STT 텍스트를 **즉시** `VOICE` 로 전송(D-029 3=b). 잠김(pending/orphaned) 중엔 마이크 숨김.
- 듣기 버튼: AI 말풍선 시간 줄 앞 24px 스피커(`aria-label` "듣기"), 재생 중 정지 아이콘("정지"), 로딩 중 `aria-busy`. 동시 재생 1개 — 다른 것을 누르면 이전 재생 중단.
- iOS: 토글·듣기·마이크 탭 제스처에서 `Audio` 1개를 무음으로 unlock 하고 재사용(D-029).
- 변환된 발화·응답은 오버레이 닫은 뒤 목록에 남는다.
