## 한 줄 요약
프로젝트명 **김영선 욕하는 앱** (슬러그 `talking-behind-my-back`, D-011).
심심이 같은 대화 앱. 로그인한 사용자가 여러 채팅방을 만들고, 각 방에서 텍스트 또는 음성으로 AI와 대화한다.
음성 대화도 텍스트로 방에 남는다. 관리자는 별도 어드민 페이지에서 앱을 관리한다.

## 아키텍처 (사용자 제시)
| 계층 | 구성 |
|---|---|
| 인프라 | Synology NAS, Docker, nginx, GitHub Actions |
| 프론트 | Next.js PWA |
| 백엔드 | Spring Boot |
| DB | MySQL + MyBatis |
| LLM API | OmniRoute (OpenAI 호환 게이트웨이, 자체 호스팅) |

## 기능 요건 (사용자 제시)
1. 소셜 로그인만 가능 (구글 / 네이버 / 카카오). 이메일·비밀번호 가입 없음.
2. 여러 개의 채팅방 개설 가능.
3. 각 채팅방은 STT/TTS 기능 지원.
4. 각 채팅방에서 음성 대화 가능. 해당 음성 대화 또한 채팅방에 텍스트로 남음.
5. 별도의 어드민 페이지로 애플리케이션 관리.

## 대화 기능 요청/응답 흐름 (사용자 제시)
1. 회원 로그인 — 앱을 종료/시작해도 세션이 남아 있음.
2. 신규 채팅방 자동 이동.
3. 대화 시작 시 채팅방 히스토리 +1.
4. 이전 채팅방에서 대화 계속 진행 가능.
5. 대화 입력 → 입력 대화 저장 → OmniRoute에 대화방 세션의 내용 전체 질의 요청 → 응답 → 응답 저장 → 응답 display, 반복.

## 확정된 해석 (DECISIONS.md 근거)
- "세션 유지" = HttpOnly refresh 쿠키(30일) 기반 자동 재로그인. (D-003)
- "신규 채팅방 자동 이동 → 대화 시작 시 히스토리 +1" = 로그인 후 빈 draft 방으로 진입, 첫 메시지 전송 시점에
  방을 실제 생성하고 사이드바 목록에 추가. 빈 방은 DB에 만들지 않는다. (D-010)
- "세션 내용 전체 질의" = 시스템 프롬프트 + 최근 N개 메시지. 전체를 무제한으로 보내지 않는다. (D-006)
- 기능 3(STT/TTS 지원)과 4(음성 대화)의 관계 = 3은 메시지 단위 버튼(듣기/말하기), 4는 "보이스 모드"
  루프(말하기 → 응답 → 자동 읽어주기 → 다시 듣기). 둘 다 결과는 텍스트 메시지로 저장. (D-007)
- STT/TTS는 서버 API 방식(OpenAI Whisper/TTS 또는 Clova). 브라우저 Web Speech API 아님. (D-007)

## 제약
- 1인 개발. 배포 대상은 NAS 한 대 (CPU/메모리 제한 — JVM 힙 768m 기준 설계).
- OmniRoute 대시보드는 LAN에서만 접근. 외부 노출 금지.
- 오디오 원본은 저장하지 않는다. 텍스트만 DB에 남긴다.
- 외부 유료 API(STT/TTS/LLM)는 비용이 발생하므로 호출 횟수·길이 상한이 설계에 포함되어야 한다.

## 용어
| 용어 | 뜻 |
|---|---|
| 방 / 채팅방 | `chat_rooms` 한 행. 사용자별로 여러 개. |
| 메시지 | `messages` 한 행. role USER/ASSISTANT, input_type TEXT/VOICE. |
| draft 방 | 아직 서버에 생성되지 않은 클라이언트 전용 빈 방 상태. |
| 보이스 모드 | 녹음→STT→응답→TTS→재녹음이 자동 반복되는 UI 상태. |
| 페르소나 | LLM 시스템 프롬프트. 어드민이 편집, 활성 1개. |
| 컨텍스트 윈도우 | LLM에 전달하는 최근 N개 메시지 + 시스템 프롬프트. |
| OmniRoute | 자체 호스팅 LLM 게이트웨이. `/v1/chat/completions` OpenAI 호환. 모델 alias로 공급자 추상화. |
